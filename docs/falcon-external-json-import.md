# Импорт JSON с тест-кейсами

Обновлено 22 сентября 2026 года. Изменения находятся в ветке `feature/import-file-library`.

Откройте импорт из репозитория или «Настройки → Импорт и экспорт». Выберите проект,
папку назначения и JSON до 5 МБ. Нажмите **Импортировать**: Falcon автоматически
распознает структуру, подготовит папки и сохранит кейсы. Отдельного преобразования
или подтверждения промежуточного результата больше нет.

Импорт открывается отдельной страницей с плавным появлением контента (без анимации
при включённом уменьшении движения). Кнопка «Импортировать» появляется после выбора
подходящего файла. Возврат выполняется общей навигацией Falcon; дополнительной
кнопки «Назад» на странице нет. Перед обработкой Falcon сохраняет точные
байты исходного JSON в приватном хранилище. Если сохранить оригинал или запись
истории не удалось, создание папок и кейсов не начинается. Повтор в том же сеансе
использует уже загруженный оригинал.

Под формой находится история файлов выбранного проекта: имя, папка назначения,
размер, автор и время сохранения. Поиск по имени и расположению работает по всей
истории, а не только по загруженной странице. Меню файла позволяет открыть JSON,
скачать оригинал, скопировать ссылку или удалить исходный файл. Ссылка открывается
только у участника с доступом к проекту. Она не содержит временного ключа хранилища.

Удаление исходника не удаляет созданные кейсы, ревизии и папки. В истории остаётся
запись с отметкой об удалении. Наличие файла в истории означает сохранение исходника,
а не успешное завершение всего импорта: итог обработки показывается отдельно.
Старые импорты, оригиналы которых ранее не сохранялись, восстановить из истории нельзя.

Экспорт Falcon v1/v2 переносится напрямую. Для внешних JSON сервер определяет поля,
шаги и группы по продуктам и разделам. При необходимости используется OpenAI;
исходный текст копирует сервер. Модель не дописывает действия или ожидаемые результаты.
Новые внешние кейсы становятся черновиками. Неизвестные поля сохраняются в тестовых
данных; процедура без ожидаемого результата остаётся в описании.

После завершения видны число сохранённых кейсов и сворачиваемое дерево структуры.
Сверьте результат с исходным экспортом. Если найденные записи не удалось обработать,
импорт останавливается до создания папок и кейсов и показывает ошибку. Записи не
исключаются молча. Форматы сторонних TMS различаются: произвольный корректный JSON
не обязательно содержит достаточно данных для полноценного тест-кейса.

Лимиты: 5 МБ и 2000 распознанных кейсов. Крупные отдельные записи могут потребовать
разделения файла. При временном сбое повторите импорт в том же окне: обработанные
пакеты и подтверждённые сохранения учитываются при продолжении. «Остановить» прекращает
дальнейшие операции; уже сохранённые кейсы остаются. После закрытия окна сначала
проверьте репозиторий, прежде чем импортировать файл повторно.

## Подготовка релиза

Нужен backend из одноимённой ветки с миграцией `0062_case_import_files.sql` и актуальным
OpenAPI. Сначала обновляются схема и backend, затем frontend. Миграция добавляет
неизменяемые записи истории, ограничения доступа по рабочему пространству и аудит
сохранения. Оригиналы используют существующую инфраструктуру приватных вложений.
Проверки готовности backend и worker должны ожидать схему 0062.

В этом проходе ничего не опубликовано и production-миграции не запускались.
Локальный визуальный стенд использует тестовые данные и транспорт; серверная
персистентность и права проверены отдельно на PostgreSQL. Реальный R2 через
production-сессию в этом проходе не проверялся.

## Проверки

- Backend: полная серия 762 теста; после согласования лимита 5 000 000 байт повторно
  пройдены пять тестов истории, включая RLS под ограниченной ролью базы.
- Проверены повторное сохранение, атомарный аудит, границы компаний и проектов,
  авторизация, поиск, пагинация и удаление исходника без удаления кейсов.
- Frontend: серия адаптеров 725 тестов; два новых теста сохранения оригинала и ссылки;
  финальный прогон `test:tms-organization` содержит 203 + 3 теста.
- Typecheck, архитектурные проверки и сборки прошли. Backend также прошёл lint,
  проверку 62 миграций и OpenAPI.
- В браузере проверены импорт синтетического JSON, просмотр, копирование ссылки,
  удаление исходника, обе темы и плотность текста при масштабе 100%.
- Событие скачивания не было подтверждено API автоматизации встроенного браузера;
  выдача доступа использует существующий attachment API с `disposition=attachment`.

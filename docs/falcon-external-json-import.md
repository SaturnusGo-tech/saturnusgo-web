# Импорт тест-кейсов из файла

Обновлено 12 ноября 2026 года.

Откройте импорт из репозитория или «Настройки → Импорт и экспорт». Выберите проект,
папку назначения и файл **JSON, CSV, TSV, XML, XLSX или XLS** размером до **5 МБ
(5 000 000 байт)**. Нажмите **Импортировать**: Falcon распознает записи, подготовит
папки и сохранит кейсы. Отдельного подтверждения промежуточного результата нет.
После завершения сверьте число кейсов, дерево папок и содержимое с исходным экспортом.

Импорт открывается отдельной страницей. Кнопка «Импортировать» появляется после
выбора подходящего файла. Возврат выполняется общей навигацией Falcon.

## Форматы и исходные сервисы

| Файл | Что переносится и что проверить |
| --- | --- |
| Экспорт Falcon v1/v2, JSON | Поддерживаемые поля кейсов, шаги или чек-листы, папки и их иерархия переносятся напрямую. |
| Внешний JSON | Поля и структура определяются по содержимому. Корректный JSON сам по себе не гарантирует наличие тест-кейсов. |
| CSV / TSV | Поддерживаются UTF-8, кавычки и переносы строк внутри ячеек. Повторяющиеся заголовки сохраняются вместе со значениями, а не перезаписывают друг друга. Несколько колонок, неоднозначно задающих одно основное поле, требуют исправления. |
| XML | Сохраняются текстовые значения, атрибуты и повторяющиеся элементы. XML должен быть корректным; DTD, объявления сущностей и неоднозначное смешение текста с дочерними элементами не поддерживаются. |
| XLSX / XLS | Сохраняются листы, колонки, исходные значения ячеек и доступные сведения о формулах. Формулы не вычисляются. XLS должен использовать контейнер OLE. |

Файлы CSV, TSV, XML и JSON должны содержать UTF-8. Переименование CSV или XML в
`.json` не преобразует файл. Длинные числовые идентификаторы и значения, которым
нужна точность, сохраняйте как текст: импорт останавливается, если число потеряет
точность при чтении. JSON с повторяющимся именем поля в одном объекте также
отклоняется до переноса данных.

Для Trello поддерживается JSON доски с карточками, списками и чек-листами.
Карточки связываются со списками и чек-листами по исходным ID. Пункты сохраняются
в порядке исходных позиций; если позиции отсутствуют у всех пунктов, используется
порядок файла. Смешение заданных и отсутствующих позиций отклоняется как неоднозначное. Карточка с пунктами становится чек-листом;
карточка без них сохраняет описание как обычный кейс. Названия доски и списка
образуют папки; `/` и `\` внутри одного названия заменяются на `／` и `＼`, чтобы не
создать лишние уровни. Исходные названия, состояние архивирования, отметки выполнения
и дополнительные поля остаются в тестовых данных. Отсутствующие связи или карточка
без названия вызывают ошибку. [Экспорт Trello](https://support.atlassian.com/trello/docs/exporting-data-from-trello/)
содержит ссылки на вложения; сами файлы вложений не переносятся по этим ссылкам автоматически.

У разных сервисов разные форматы экспорта. Встроенный экспорт задач
[Linear](https://linear.app/docs/exporting-data) использует CSV, а JSON можно получить
через API. Для [Jira](https://support.atlassian.com/jira-software-cloud/docs/export-search-results/)
документированы CSV и XML; JSON ответа REST API отличается от этих файлов. Формат
[TestRail XML](https://support.testrail.com/hc/en-us/articles/15144643126932-Export-test-cases) сохраняет разделы и кейсы; CSV может содержать выбранные колонки или
несколько строк на один кейс. Доступность загрузки такого файла не означает
поддержку всех настроек и версий его экспорта.

Для названий **DocQA / DockQA** отдельная схема экспорта не подтверждена и специальный
адаптер не заявлен. Такой файл обрабатывается по общим правилам своего формата;
для гарантированного переноса нужна проверка конкретной структуры исходных данных.

**Allure TestOps и Allure Report — разные источники.** Файл `*-result.json` Allure
Report описывает один запуск теста и не равнозначен экспорту репозитория ручных кейсов
из TestOps. Статусы `passed` / `failed`, длительность и отметки выполнения пунктов
не превращаются в ожидаемые результаты или историю запусков Falcon. Для миграции
базы кейсов используйте экспорт самих кейсов и отдельно проверяйте его полноту.

Эти форматы доступны на странице импорта Falcon. Импорт файлов через MCP по-прежнему
принимает JSON.

## Содержимое и полнота переноса

Для внешних данных сервер определяет поля, шаги и группы по продуктам и разделам.
При необходимости OpenAI помогает определить структуру; исходный текст копирует
сервер. Модель не дописывает действия, ожидаемые результаты или пропущенные пункты.
Новые внешние кейсы становятся черновиками. Дополнительные поля сохраняются в
тестовых данных в пределах допустимого размера.

Чек-лист остаётся чек-листом: его пункты не получают выдуманные ожидаемые результаты.
Обычная процедура без ожидаемого результата сохраняется в описании. Исходная отметка
«выполнено» у пункта Trello или Markdown-чекбокса сохраняется как сведения об источнике,
а не как результат проверки Falcon.

Каждая найденная запись и каждый распознанный пункт должны быть учтены. Если запись
нельзя обработать, импорт останавливается до создания папок и кейсов. Записи и
неподдержанные пункты не исключаются молча. Неполные страницы известных API, ошибки
GraphQL, отсутствующие связанные чек-листы и неразрешённые общие шаги TestRail
отклоняются. Общий шаг, уже содержащий исходный текст действия, можно обработать
без запроса его определения. Завершите экспорт всех страниц и связанных данных
перед повторной загрузкой.

## Оригинал файла и история

Перед серверной нормализацией Falcon сохраняет **точные байты исходного файла**
в приватном хранилище. Это относится и к двоичным XLSX/XLS: в истории хранится
оригинал, а не JSON, полученный при чтении таблицы. Если сохранить файл или запись
истории не удалось, создание папок и кейсов не начинается. Повтор в том же сеансе
использует уже загруженный оригинал.

Под формой находится история файлов выбранного проекта: имя, папка назначения,
размер, автор и время сохранения. Поиск по имени и расположению работает по всей
истории. Меню позволяет открыть или скачать файл, скопировать ссылку и удалить
исходник. Ссылка доступна только участнику с доступом к проекту и не содержит
временного ключа хранилища.

Удаление исходника не удаляет созданные кейсы, ревизии и папки. В истории остаётся
запись об удалении. Наличие оригинала в истории подтверждает его сохранение;
результат переноса показывается отдельно. После ошибки обработки запись истории
может сохраниться. Старые оригиналы, которые ранее не сохранялись, восстановить
из истории нельзя.

## Лимиты и продолжение

- До 5 000 000 байт исходного файла и 2000 распознанных кейсов.
- До 500 шагов или пунктов чек-листа и 100 тегов на кейс. Описание, предусловия,
  тестовые данные и текст отдельного пункта ограничены 20 000 символов.
- Для таблиц: до 32 листов, 256 колонок, 100 000 заполненных ячеек; лимит 2000 записей
  общий для всех листов. Для XLSX дополнительно проверяются содержимое ZIP-контейнера,
  лимит 20 000 000 байт после распаковки и 4096 записей архива. Зашифрованные книги
  не поддерживаются.

Глубокие структуры и крупные отдельные записи могут потребовать разделения файла
или упрощения структуры. Данные не обрезаются для обхода лимита. Если дополнительные
поля одной записи не помещаются в тестовые данные, обработка завершается ошибкой.

При временном сбое продолжите импорт в том же окне: обработанные пакеты и
подтверждённые сохранения учитываются при продолжении. «Остановить» прекращает
дальнейшие операции; уже сохранённые кейсы остаются. После закрытия окна сначала
проверьте репозиторий, прежде чем загружать файл повторно.

## Подготовка релиза

Для расширенных форматов нужен backend с миграцией
`0131_case_import_source_formats.sql` и соответствующим OpenAPI. Миграция сохраняет
приватное хранение, неизменяемую историю и аудит, добавляя допустимые сочетания
формата и имени исходного файла. Сначала обновляются схема и backend, затем frontend.

Backend поддерживает проверку готовности для схем 0130–0131; выпуск с расширенными
форматами должен ожидать применённую схему **0131**. Проверки backend, worker и
release workflow должны согласованно использовать этот номер. Первоначальная
миграция истории `0062_case_import_files.sql` уже входит в предыдущие схемы и не
заменяет миграцию 0131.

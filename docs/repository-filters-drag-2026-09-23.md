# Фильтры и перенос в репозитории

## Объём релиза

Выбран второй визуальный вариант только для фильтров. Диалог «Новая папка» не менялся. Релиз включает ранее согласованное создание подпапки на месте и небольшой плюс в строке кейса из `e5c0f36ee`.

## Фильтры

- Одно окно с категориями слева и значениями справа, без перехода на вложенные экраны.
- Реальные статусы Falcon сохранены: готово, черновик, устарел. Эскиз не меняет бизнес-модель.
- Выбор разных категорий суммируется. Поиск не очищает выбранные папки/компоненты. Сброс очищает и дополнительные фильтры потребителя.
- Поповер находится в native top layer; контейнер дерева или drawer не обрезает его. Положение ограничено окном, списки прокручиваются внутри. Для очень низкого окна используется доступная высота с отступом 12 px.
- Arrow Up/Down/Home/End переключают категории или значения; Arrow Right переводит фокус к значениям. Escape закрывает меню и возвращает фокус к кнопке.
- Сохранены общие фильтры выбора кейсов для прогонов и наборов, включая ответственных и дополнительные категории.

## Перенос

- Удержание строки 260 мс начинает перенос. Набор выбранных ID фиксируется в момент захвата, включая кейсы из разных папок.
- Кейсы собираются в компактную стопку с количеством; исходные строки приглушаются без изменения высоты. Reduced motion отключает анимацию.
- Только допустимая папка подсвечивается. Закрытая папка раскрывается после 650 мс наведения. После drop назначение и его родители остаются раскрытыми.
- Корневая зона на время жеста получает подпись «В корень репозитория».
- Запрещены циклы, перенос в архив, недоступное назначение, изменение во время другой команды и перенос без прав. Escape отменяет жест. При ошибке выбор сохраняется.
- Используются существующие атомарные команды API. Перенос папки обновляет пути потомков и кейсов, сохраняет ID и содержимое ревизий. Обновляются оба ресурса: кейсы и дерево.

## Проверки

- TypeScript и архитектурная проверка: успешно (1 207 исходных файлов).
- Полный `test:tms-adapters`: 750 тестов, 0 ошибок, 0 пропусков (523 + 219 + 3 + 5).
- Реальный изолированный PostgreSQL: 11 интеграционных проверок папок и переносов. Проверены вложенность, возврат в корень, пакетный перенос, ограничения прав/области, архив, конфликт имени, ETag, идемпотентность и неизменность ревизий.
- Браузер: светлая/тёмная темы, ширина 390 px, высота 360 px, клавиатура, мультивыбор из разных папок, стопка и сохранение раскрытия после переноса.
- Standalone-стенд использует настоящие компоненты и управляемые тестовые данные. Его переносы не записываются в production. Серверная логика отдельно проверена на PostgreSQL.
- Backend runtime и схема БД в этом релизе не меняются.

Снимки и артефакты: `output/falcon-filters-drag-20260923/` в родительском рабочем каталоге. Итог публикации фиксируется отдельно в `release/release-record.json`.

## Контракт высоты поповера: Safari и Chromium

В Safari обнаружено схлопывание окна до заголовка и части содержимого при исправном отображении в Chromium. Причина в расчёте естественной высоты вложенных flex/grid-контейнеров внутри native popover. Для тела и содержимого используется `flex-basis: auto`; строка grid и прокручиваемые области могут сжиматься до доступной высоты. Не восстанавливать жёсткую минимальную высоту содержимого: она обрезает нижние действия на низком экране.

`filter-popup.test.ts` проверяет координаты, ограничение размеров и закрытие на модели DOM. Он не запускает CSS layout engine и не обнаружит эту регрессию. Проверка строк CSS также не доказывает корректное отображение.

После изменения размеров поповера проверить в настоящих Safari и Chromium:

1. Открыть фильтры в репозитории и в drawer создания прогона при обычном размере окна. Должны быть доступны категории, значения, переключатель архива и сброс; тело не схлопывается до заголовка.
2. Переключить статус, папки с длинным списком, ответственных и пустой результат поиска. Прокручивается список; заголовок и нижние действия остаются видимыми и доступны мышью и клавиатурой.
3. Повторить в обеих темах, при ширине 390 px и высоте 360 px. Окно остаётся внутри viewport, до последних значений можно дойти прокруткой. Для проверки использовать реальные размеры окна либо временное изменение viewport, затем восстановить исходный размер.
4. Сохранить снимок и размеры окна отдельно для каждого браузера. Проверка только в Chromium не подтверждает исправление Safari.
